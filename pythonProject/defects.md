## BUG-001：残缺帧导致从机永久失联

**严重程度**：高（设备必须复位才能恢复）
**发现方式**：自动化回归测试

### 现象

从机正常工作一段时间后突然不再响应任何请求。串口能正常打开，但收不到任何返回。
**必须按复位键或重新上电才能恢复。**

这是典型的**静默失效（silent failure）**：设备看起来还活着（电源灯亮、串口能打开），
但功能已经死了。比崩溃更难排查。

### 复现步骤

1. 烧录缺陷版固件（按字节数断帧）
2. 发送一帧**不完整的报文**（只有 5 字节，缺数量和 CRC）：
   ```
   01 03 00 00 00
   ```
3. 等待 200ms
4. 发送一帧**完整的合法报文**：
   ```
   01 03 00 00 00 01 84 0A
   ```
5. 观察：**无任何响应**。此后发送任何报文均无响应。

### 实测证据

`tools/repro_bug001.py` 输出（修复前）：

```
=== BUG-001 复现 === 端口 COM3

  ① 正常读（基线）      发送 01 03 00 00 00 01 84 0A  -> 有响应  01 03 02 00 00 B8 44

  >>> 现在发送一帧残缺报文（只有 5 字节）
  ② 残缺帧后正常读      发送 01 03 00 00 00 01 84 0A  -> 无响应
  ③ 再发一次正常读      发送 01 03 00 00 00 01 84 0A  -> 无响应

=== 结论 ===
  ✅ 复现成功：BUG-001 存在
```

同期 `pytest -q` 结果：**25 failed, 75 passed**

### 根因

`modbus_slave.c` 的 `Modbus_Poll()`：

```c
if (s_rx_len >= need)
{
    ProcessFrame(s_rx, need);
    s_rx_len = 0;          /* 只有攒够 need 字节才清零 */
}
```

`s_rx_len` **只在"攒够整帧"时清零**。

收到残缺帧后，缓冲里残留 1~7 个字节，`s_rx_len` 永远小于 `need`，
后续新字节全部追加在残帧后面 → **帧头永久错位** → CRC 永远校验失败 → 永久死锁。

### 修复

`modbus_slave.c` 的 `Modbus_Poll()` 改为两层保护：

```c
now = BSP_TIMER_GetMs();
if (s_rx_len > 0)
{
    elapsed = now - s_last_rx_ms;

    if (elapsed >= MODBUS_T35_MS)              /* 4ms 空闲 → 一帧结束 */
    {
        ProcessFrame(s_rx, s_rx_len);
        s_rx_len = 0;
    }
    else if (elapsed >= MODBUS_RX_TIMEOUT_MS)  /* 50ms 兜底强制清空 */
    {
        s_rx_len = 0;
    }
}
```

| 层次 | 机制 | 作用 |
|---|---|---|
| 正常路径 | 3.5 字符空闲断帧（4ms） | 符合 Modbus RTU 标准 |
| 兜底路径 | 50ms 接收超时强制清空 | 任何异常字节流都不可能造成永久死锁 |

### 修复验证

同一脚本，修复后输出：

```
  ① 正常读（基线）      发送 01 03 00 00 00 01 84 0A  -> 有响应  01 03 02 00 00 B8 44
  ② 残缺帧后正常读      发送 01 03 00 00 00 01 84 0A  -> 有响应  01 03 02 00 00 B8 44
  ③ 再发一次正常读      发送 01 03 00 00 00 01 84 0A  -> 有响应  01 03 02 00 00 B8 44

=== 结论 ===
  ❌ 未复现：残缺帧后仍能正常响应（固件已修复）
```

随后 `pytest -q`：**100 passed**

## BUG-002：按功能码推算长度，无法正确处理粘包

**严重程度**：中（会触发 BUG-001，导致设备失联）

### 现象

两帧零间隔连发时，从机把 16 字节当作一帧处理，CRC 失败后丢弃。
但由于 `s_rx_len` 在丢弃后错误地残留，进而触发 BUG-001。

### 复现步骤

一次性把两帧完整报文写入串口（零间隔）：

```
01 03 00 00 00 04 44 09 01 03 00 00 00 0A C5 CD
```

观察：无响应，且此后从机不再响应。

### 根因

`s_rx[1]` 的功能码只能决定**单帧**长度，无法确定帧边界。
帧边界只能由**时间**（3.5 字符空闲）或 **长度字段 + CRC** 共同确定。

### 修复

与 BUG-001 同源，改回空闲超时断帧即可。

### 回归用例

| 用例 | 覆盖点 |
|---|---|
| `test_reg_bug002_sticky_frames_no_side_effect` | 两帧粘包后设备可继续工作 |
| `test_reg_bug002_three_frames_sticky` | 三帧粘包同样不残留状态 |
